The idea

A nested condition checks a second rule only after a first rule holds. It can model dependent decisions, but deep nesting is hard to inspect. Guard clauses and small functions often make the rules clearer.

A complete program to try.

BEFORE YOU RUN

Save the entire program in nested_if.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

This program uses only Python’s standard library; no extra package is needed.

Run: python nested_if.py

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
user = {"active": True, "role": "editor"}
if user["active"]:
    if user["role"] == "editor":
        print("Editing allowed")
    else:
        print("Read only")
else:
    print("Account disabled")
EXPECTED RESULT
Editing allowed

Read it step by step.

Read from the top. A function or class body does not run just because you defined it; look for the call, or let pytest call a test function.

  1. Line 1: Bind user to the result of {'active': True, 'role': 'editor'}. Assignment gives a value a name; it does not automatically copy a nested object.
  2. Line 2: Evaluate user['active']. Run the matching indented branch; the other branch is skipped.

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Which if does an else belong to in nested Python code?

The if at the matching indentation level. Python uses indentation as syntax, so moving else changes the decision tree. Test each combination of dependent conditions.

Which common mistake can affect this program or test?

An else belongs to the if at the same indentation level, not necessarily the nearest-looking condition.
