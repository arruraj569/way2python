The idea

An API framework needs a configuration boundary, a client fixture, data builders, behavioral tests, cleanup, and reports. Run a known local service in CI, wait for health readiness, and preserve a failing exit code from the tests.

A complete program to try.

BEFORE YOU RUN

Save the entire program in test_api_automation_framework_and_ci_pipeline.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

Install once in your activated environment: python -m pip install pytest requests.

Start the local API service first: python mock_api.py --port 8765 from the unzipped practice kit. Keep that terminal running, and run the program in a second activated terminal.

Run: python -m pytest test_api_automation_framework_and_ci_pipeline.py -q

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
import requests
def test_health_contract():
    response = requests.get("http://127.0.0.1:8765/health", timeout=5)
    assert response.status_code == 200
    assert response.headers["Content-Type"].startswith("application/json")
    assert response.json() == {"status": "ok"}
EXPECTED RESULT
1 passed with the local API running. Run with --junitxml=reports/api.xml to create a CI-readable artifact.

Read it step by step.

Read from the top. A function or class body does not run just because you defined it; look for the call, or let pytest call a test function.

  1. Line 1: Import requests. This makes the named library tools available; third-party packages must be installed first.
  2. Line 2: Define test_health_contract(). Its body runs when called by pytest, which supplies fixture arguments.
  3. Line 3: Bind response to the result of requests.get('http://127.0.0.1:8765/health', timeout=5). Assignment gives a value a name; it does not automatically copy a nested object.
  4. Line 4: Check response.status_code == 200. The program continues if this is true and raises AssertionError if it is false.
  5. Line 5: Check response.headers['Content-Type'].startswith('application/json'). The program continues if this is true and raises AssertionError if it is false.
  6. Line 6: Check response.json() == {'status': 'ok'}. The program continues if this is true and raises AssertionError if it is false.

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Why is generating a report not enough to make CI enforce passing tests?

The job must preserve a nonzero test exit code when a required case fails. A later successful shell command can obscure it if the script does not handle status correctly. Publish artifacts without changing failure into success.

Which common mistake can affect this program or test?

Do not swallow test exit codes in shell scripts. Assertions should include context while excluding secrets.
