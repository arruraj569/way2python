Fixtures, scopes and teardown

pytest toolkit · Complete program, tricky exercise, and interview answers

First time writing Python?Start from zero →Read the punctuation guide ↗

The idea

A fixture provides a dependency to a test by name. Function scope usually gives the clearest isolation. A yield fixture places cleanup after the test. Choose a broader scope only when sharing the resource is safe.

A complete program to try.

BEFORE YOU RUN

Save the entire program in test_fixtures_scopes_and_teardown.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

Install once in your activated environment: python -m pip install pytest.

Run: python -m pytest test_fixtures_scopes_and_teardown.py -q

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
import pytest
@pytest.fixture
def users():
    records = []
    yield records
    records.clear()

def test_add_user(users):
    users.append({"name": "Mira"})
    assert len(users) == 1

def test_isolated_users(users):
    assert users == []
EXPECTED RESULT
Run as a test file: 2 passed; each test receives a fresh list.

Read it step by step.

Read from the top. A function or class body does not run just because you defined it; look for the call, or let pytest call a test function.

  1. Line 1: Import pytest. This makes the named library tools available; third-party packages must be installed first.
  2. Line 3: Define users(). Its body runs when called, rather than just because the definition was read.
  3. Line 8: Define test_add_user(users). Its body runs when called by pytest, which supplies fixture arguments.
  4. Line 9: Call users.append with the shown arguments. Read its result contract before assuming a successful call means the behavior was correct.
  5. Line 10: Check len(users) == 1. The program continues if this is true and raises AssertionError if it is false.

TRICKY PYTHON PROGRAM
from contextlib import contextmanager
@contextmanager
def fixture_like():
    print("setup")
    try: yield []
    finally: print("teardown")

try:
    with fixture_like() as values:
        values.append(1)
        assert len(values) == 0
except AssertionError:
    print("test failed")

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Why should fixture teardown be independent of a test passing?

A failed test must still release sessions and remove its data. A yield fixture runs its post-yield teardown after the test. Setup failures before yield need cleanup that covers any resource already acquired.

Which common mistake can affect this program or test?

A session-scoped mutable object can leak data across tests. Cleanup must also handle partially completed setup.
