The idea

An instance method uses self, a class method receives cls, and a static method receives neither automatically. A class method is useful for alternative construction; a static method can group a closely related utility.

A complete program to try.

BEFORE YOU RUN

This program uses only Python’s standard library; no extra package is needed.

COMPLETE PYTHON PROGRAM
class BrowserConfig:
    def __init__(self, name):
        self.name = name
    def label(self):
        return self.name.upper()
    @classmethod
    def default(cls):
        return cls("chromium")
    @staticmethod
    def supported(name):
        return name in {"chromium", "firefox", "webkit"}

print(BrowserConfig.default().label())
print(BrowserConfig.supported("firefox"))
EXPECTED RESULT
CHROMIUM
True

TRICKY PYTHON PROGRAM
class Base:
    @classmethod
    def name(cls):
        return cls.__name__
    @staticmethod
    def fixed():
        return "Base"
class Child(Base):
    pass

print(Child.name(), Child.fixed())

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Why is a classmethod often suitable for an alternate constructor?

It receives the actual calling class, so cls(...) can construct a subclass when inherited. A staticmethod has no implicit instance or class argument and cannot get that behavior automatically.

Which common mistake can affect this program or test?

A static method that does not belong conceptually to the class may be simpler as a module function.
