Iterator in Python and Selenium

Behavioral patterns · Complete program, tricky exercise, and interview answers

First time writing Python?Start from zero →Read the punctuation guide ↗

The idea

An iterator returns items one at a time through the iteration protocol. Python generators implement this simply. A factory that returns a new generator supports repeatable traversal.

Behavioral patterns · Everyday

Use it in daily work.

Read test cases or table row texts one at a time in a daily report. Prefer a stable snapshot if clicking rows causes the DOM to redraw.

Know the tradeoff.

Generators are usually consumed once. Do not reuse an exhausted iterator or assume stored WebElements remain valid after navigation.

"""Run against the local Way2Python lab with Selenium and installed Chrome."""
import os
from contextlib import contextmanager
from copy import deepcopy
from dataclasses import dataclass
from urllib.parse import urlsplit
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait, Select
from selenium.webdriver.support import expected_conditions as EC
from selenium.common.exceptions import TimeoutException

BASE_URL = os.getenv("WAY2PYTHON_URL", "http://localhost:8080/way2python").rstrip("/")

def create_driver():
    options = webdriver.ChromeOptions()
    options.add_argument("--headless=new")
    return webdriver.Chrome(options=options)

@contextmanager
def browser_session(factory=create_driver):
    driver = factory()
    try:
        driver.get(BASE_URL + "/practice.html")
        yield driver
    finally:
        driver.quit()

def control(driver, selector):
    return WebDriverWait(driver, 5).until(
        EC.element_to_be_clickable((By.CSS_SELECTOR, selector)))

def fill(driver, selector, value):
    field = control(driver, selector)
    field.clear()
    field.send_keys(value)

def wait_text(driver, selector, expected):
    WebDriverWait(driver, 5).until(
        lambda current: current.find_element(By.CSS_SELECTOR, selector).text == expected)
    return driver.find_element(By.CSS_SELECTOR, selector).text

def login(driver, email="learner@example.test", password="python123"):
    fill(driver, "#email", email)
    fill(driver, "#password", password)
    control(driver, "#login-form button[type=submit]").click()

def save_profile(driver, name, track="selenium"):
    fill(driver, "#display-name", name)
    Select(control(driver, "#track-select")).select_by_value(track)
    control(driver, "#save-profile").click()


def task_names(driver):
    # Snapshot strings, not WebElement objects that may become stale.
    names = [element.text for element in driver.find_elements(By.CSS_SELECTOR, "#task-rows tr td:first-child")]
    yield from names

def main():
    with browser_session() as driver:
        for name in ("Login smoke", "Profile smoke"):
            fill(driver, "#task-name", name)
            control(driver, "#add-task").click()
        names = task_names(driver)
        assert list(names) == ["Login smoke", "Profile smoke"]
        assert list(names) == []
    print('Task-name iterator passed')

if __name__ == "__main__":
    main()
EXPECTED RESULT WHEN RUN LOCALLY
Task-name iterator passed
Read the Selenium program step by step
  1. Imports provide browser creation, locators, waits and select controls.
  2. browser_session creates a fresh browser, opens the local lab, and quits in finally. Factory and template examples own this context inside their workflow.
  3. fill clears a field before typing. wait_text polls for the exact observed result instead of pausing for an arbitrary delay.
  4. The pattern’s classes or functions sit between these helpers and main. Follow main to see the actual journey and assertions.
  5. The final message prints only after assertions succeed and the owned browser closes.

Iterable versus iterator?

An iterable can provide an iterator via iter. An iterator supplies successive values via next and is exhausted at StopIteration. A list can create fresh iterators; a generator object is itself a one-pass iterator.

Which common mistake can affect this program or test?

Generators are usually consumed once. Do not reuse an exhausted iterator or assume stored WebElements remain valid after navigation.
