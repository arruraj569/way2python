The idea

A module is an importable Python file; a package organizes modules. Keep reusable clients, page objects, data builders, and tests in separate folders with clear responsibilities. A regular package contains __init__.py.

A complete program to try.

BEFORE YOU RUN

Save the entire program in modules_and_packages.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

This program uses only Python’s standard library; no extra package is needed.

Run: python modules_and_packages.py

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
# Put this function in helpers.py.
def build_email(name):
    return f"{name.lower()}@example.test"

# From another file: from helpers import build_email
print(build_email("Mira"))
EXPECTED RESULT
mira@example.test

Read it step by step.

Read from the top. A function or class body does not run just because you defined it; look for the call, or let pytest call a test function.

  1. Line 2: Define build_email(name). Its body runs when called, rather than just because the definition was read.
  2. Line 6: Print build_email('Mira') to the terminal. print displays values and returns None.

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

What happens when your file is named the same as a library you import?

Python’s import path may resolve your local file instead of the intended library, causing missing attributes or circular imports. Rename the file, remove stale bytecode if needed, and inspect the imported module’s __file__.

Which common mistake can affect this program or test?

Avoid editing sys.path to paper over a confusing layout. Use a package and run through python -m when appropriate.
