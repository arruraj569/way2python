CSV files and data-driven cases

Files & structured data · Complete program, tricky exercise, and interview answers

First time writing Python?Start from zero →Read the punctuation guide ↗

The idea

csv.DictReader turns rows into dictionaries using the header fields. CSV stores text, so convert numeric and boolean fields explicitly. Use newline="" when opening real CSV files to let the module handle line endings.

A complete program to try.

BEFORE YOU RUN

Save the entire program in csv_files_and_data_driven_cases.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

This program uses only Python’s standard library; no extra package is needed.

Run: python csv_files_and_data_driven_cases.py

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

csv_files_and_data_driven_cases.pyDownload program ↓
COMPLETE PYTHON PROGRAM
import csv
from io import StringIO
text = "name,expected\nvalid,201\ninvalid,422\n"
cases = list(csv.DictReader(StringIO(text)))
for case in cases:
    print(case["name"], int(case["expected"]))
EXPECTED RESULT
valid 201
invalid 422

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Why is splitting on commas and trusting CSV numeric inference unsafe?

Quoted fields can contain commas or newlines, and csv.DictReader returns field text. Use the CSV parser and explicitly convert each typed field, with clear validation for invalid text.

Which common mistake can affect this program or test?

Never split CSV rows with a plain comma: quoted fields may themselves contain commas or newlines.
