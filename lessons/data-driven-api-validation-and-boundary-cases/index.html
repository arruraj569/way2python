The idea

Use a case table to exercise missing fields, empty strings, malformed values, and maximum-length boundaries. Keep the expected error explicit for each case. The practice API requires a trimmed name of 1–100 characters and a simply validated email.

A complete program to try.

BEFORE YOU RUN

Save the entire program in test_data_driven_api_validation_and_boundary_cases.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

Install once in your activated environment: python -m pip install pytest requests.

Start the local API service first: python mock_api.py --port 8765 from the unzipped practice kit. Keep that terminal running, and run the program in a second activated terminal.

Run: python -m pytest test_data_driven_api_validation_and_boundary_cases.py -q

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
import pytest
import requests
@pytest.mark.parametrize("payload", [
    {"email": "mira@example.test"},
    {"name": "", "email": "mira@example.test"},
    {"name": "Mira", "email": "not-an-email"},
    {"name": "x" * 101, "email": "mira@example.test"},
], ids=["missing-name", "empty-name", "malformed-email", "name-too-long"])
def test_reject_invalid(payload):
    response = requests.post("http://127.0.0.1:8765/users",
        headers={"Authorization": "Bearer demo-token"}, json=payload, timeout=5)
    assert response.status_code == 422
    assert response.json()["error"] == "validation_error"
EXPECTED RESULT
4 passed with the local API running.

  3. Line 9: Define test_reject_invalid(payload). Its body runs when called by pytest, which supplies fixture arguments.
  4. Line 10: Bind response to the result of requests.post('http://127.0.0.1:8765/users', headers={'Authorization': 'Bearer demo-token'}, json=payload, …. Assignment gives a value a name; it does not automatically copy a nested object.
  5. Line 12: Check response.status_code == 422. The program continues if this is true and raises AssertionError if it is false.
  6. Line 13: Check response.json()['error'] == 'validation_error'. The program continues if this is true and raises AssertionError if it is false.

payloads = [{}, {"name": None}, {"name": ""}, {"name": " "}]
for payload in payloads:
    present = "name" in payload
    value = payload.get("name")
    valid = isinstance(value, str) and bool(value.strip())
    print(present, valid)

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Why should missing, null, empty and whitespace-only inputs be separate cases?

They can traverse different parsing and validation paths and produce different error locations. State the contract for each, use readable IDs, and test accepted as well as rejected boundaries.

Which common mistake can affect this program or test?

The exact status code is an application contract. Do not assume every API returns 422 for invalid input.
