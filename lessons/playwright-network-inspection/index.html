State & debugging · Complete program, tricky exercise, and interview answers

The idea

Browser journeys can be checked alongside their network traffic. Register a response listener before triggering an action. In a real application, assert the relevant endpoint’s status and payload while still verifying visible behavior.

A complete program to try.

BEFORE YOU RUN

Save the entire program in test_playwright_network_inspection.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

Install once in your activated environment: python -m pip install pytest-playwright.

Install Chromium once: python -m playwright install chromium. Browser test files use fixtures supplied by the pytest plugin.

The Way2Python site must be running at localhost:8080/way2python. Selenium also needs an installed browser such as Chrome.

Run: python -m pytest test_playwright_network_inspection.py -q --base-url http://localhost:8080/way2python

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
from playwright.sync_api import Page, expect

def test_practice(page: Page, base_url):
    page.goto(f"{base_url}/practice.html")
    seen = []
    page.on("response", lambda response: seen.append(response.url))
    page.reload()
    expect(page.get_by_role("heading", name="A small lab. Real browser skills.")).to_be_visible()
    assert any("practice.html" in url for url in seen)
EXPECTED RESULT
1 passed; the document response is observed on reload.

Read it step by step.

Read from the top. A function or class body does not run just because you defined it; look for the call, or let pytest call a test function.

  1. Line 1: Import playwright.sync_api. This makes the named library tools available; third-party packages must be installed first.
  2. Line 3: Define test_practice(page, base_url). Its body runs when called by pytest, which supplies fixture arguments.
  3. Line 4: Navigate the browser to the indicated application page. The target site must be running and reachable.
  4. Line 5: Bind seen to the result of []. Assignment gives a value a name; it does not automatically copy a nested object.
  5. Line 6: Call page.on with the shown arguments. Read its result contract before assuming a successful call means the behavior was correct.
  6. Line 7: Call page.reload with the shown arguments. Read its result contract before assuming a successful call means the behavior was correct.
  7. Line 8: Check the browser’s observable state with a retrying Playwright expectation. It must become correct before the timeout.
  8. Line 9: Check any(('practice.html' in url for url in seen)). The program continues if this is true and raises AssertionError if it is false.

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Why should a response wait identify the relevant endpoint precisely?

An unrelated analytics or document request can succeed while the business request fails. Match the correct method and endpoint, then inspect its status and payload alongside visible UI behavior.

Which common mistake can affect this program or test?

The static lab has no network-backed save endpoint. Its UI interactions are not proof of server behavior.
