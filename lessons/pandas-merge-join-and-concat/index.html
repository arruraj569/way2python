pandas merge, join and concat

pandas for automation · Complete program, tricky exercise, and interview answers

First time writing Python?Start from zero →Read the punctuation guide ↗

The idea

merge connects tables by keys; concat stacks compatible data. Choose join semantics deliberately and validate the expected relationship. A duplicated key can multiply rows and inflate failure counts without an obvious error.

A complete program to try.

BEFORE YOU RUN

Save the entire program in pandas_merge_join_and_concat.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

Install once in your activated environment: python -m pip install pandas.

Run: python pandas_merge_join_and_concat.py

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
import pandas as pd
tests = pd.DataFrame({"suite": ["auth", "catalog"], "failures": [2, 1]})
owners = pd.DataFrame({"suite": ["auth", "catalog"], "owner": ["Team A", "Team B"]})
joined = tests.merge(owners, on="suite", how="left", validate="one_to_one")
print(joined["owner"].tolist())
EXPECTED RESULT
['Team A', 'Team B']

TRICKY PYTHON PROGRAM
import pandas as pd
left = pd.DataFrame({"key": [1, 1], "test": ["a", "b"]})
right = pd.DataFrame({"key": [1, 1], "owner": ["X", "Y"]})
print(len(left.merge(right, on="key")))
try:
    left.merge(right, on="key", validate="one_to_one")
except pd.errors.MergeError:
    print("duplicate key relationship rejected")

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

How can a join inflate counts without creating an obvious syntax error?

Repeated keys on both sides create many-to-many row combinations. Validate the intended relationship and reconcile counts before aggregating. Check unmatched rows when every record requires a mapping.

Which common mistake can affect this program or test?

Do not silently drop unmapped suites using an inner join when every suite needs an owner.
