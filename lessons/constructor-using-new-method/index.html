Constructor using __new__() method

Objects & methods · Complete program, tricky exercise, and interview answers

The idea

__new__ creates an instance and runs before __init__. You rarely need to override it in automation code. One useful example is customizing creation of an immutable type, whose value cannot be assigned afterward.

A complete program to try.

BEFORE YOU RUN

Save the entire program in constructor_using_new_method.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

This program uses only Python’s standard library; no extra package is needed.

Run: python constructor_using_new_method.py

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
class NormalizedName(str):
    def __new__(cls, value):
        return super().__new__(cls, value.strip().lower())

name = NormalizedName("  LOGIN  ")
print(name, isinstance(name, str))
EXPECTED RESULT
login True

Read it step by step.

Read from the top. A function or class body does not run just because you defined it; look for the call, or let pytest call a test function.

  1. Line 1: Define the class NormalizedName. It groups related data and methods; constructing an instance and calling methods happens later.
  2. Line 5: Bind name to the result of NormalizedName(' LOGIN '). Assignment gives a value a name; it does not automatically copy a nested object.
  3. Line 6: Print name, isinstance(name, str) to the terminal. print displays values and returns None.

class Factory:
    def __new__(cls):
        return "not a Factory instance"
    def __init__(self):
        print("initializing")

value = Factory()
print(type(value).__name__)

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

When can __init__ be skipped after __new__?

If __new__ returns an object that is not an instance of the requested class, its normal __init__ is not called. This is an advanced creation rule and is rarely needed in test frameworks.

Which common mistake can affect this program or test?

For ordinary mutable classes, use __init__. Singleton patterns can introduce unwanted shared state between tests.
