Dates, time zones and durations

Configuration & tools · Complete program, tricky exercise, and interview answers

First time writing Python?Start from zero →Read the punctuation guide ↗

The idea

Use timezone-aware timestamps when recording events and monotonic clocks when measuring elapsed time. A wall clock can change during a run. Compare dates in a deliberate timezone rather than relying on the machine default.

A complete program to try.

BEFORE YOU RUN

Save the entire program in dates_time_zones_and_durations.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

This program uses only Python’s standard library; no extra package is needed.

Run: python dates_time_zones_and_durations.py

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
from datetime import datetime, timezone
import time
stamp = datetime(2026, 10, 12, 10, 0, tzinfo=timezone.utc)
print(stamp.isoformat())
start = time.perf_counter()
assert time.perf_counter() - start >= 0
EXPECTED RESULT
2026-10-12T10:00:00+00:00

TRICKY PYTHON PROGRAM
from datetime import datetime, timezone
naive = datetime(2026, 10, 12, 10)
aware = datetime(2026, 10, 12, 10, tzinfo=timezone.utc)
try:
    print(aware - naive)
except TypeError:
    print("cannot subtract aware and naive timestamps")

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

When should you use a wall-clock timestamp versus a monotonic clock?

Use a timezone-aware wall clock for event times and a monotonic or performance clock for elapsed durations. Wall time can be adjusted during a run, while duration measurement should not jump with clock corrections.

Which common mistake can affect this program or test?

Subtracting naive and aware datetime values raises an error. A fixed sleep is also not a readiness check.
