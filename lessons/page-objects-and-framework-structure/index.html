Page objects and framework structure

Framework & CI · Complete program, tricky exercise, and interview answers

The idea

Organize a framework around responsibilities: tests state business expectations, page objects express UI actions, clients express HTTP operations, and fixtures own setup and cleanup. Share simple helpers only after repeated needs are clear.

A complete program to try.

BEFORE YOU RUN

Save the entire program in test_page_objects_and_framework_structure.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

Install once in your activated environment: python -m pip install pytest requests.

Start the local API service first: python mock_api.py --port 8765 from the unzipped practice kit. Keep that terminal running, and run the program in a second activated terminal.

Run: python -m pytest test_page_objects_and_framework_structure.py -q

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

COMPLETE PYTHON PROGRAM
import requests
import pytest
from uuid import uuid4

def build_user():
    return {"name": "Mira", "email": f"{uuid4().hex}@example.test"}

class UsersClient:
    def __init__(self, session):
        self.session = session
        self.root = "http://127.0.0.1:8765/users"
    def create(self, data):
        return self.session.post(self.root, json=data, timeout=5)
    def remove(self, identity):
        return self.session.delete(f"{self.root}/{identity}", timeout=5)

@pytest.fixture
def users_client():
    with requests.Session() as session:
        session.headers["Authorization"] = "Bearer demo-token"
        yield UsersClient(session)

def test_create_user(users_client):
    data = build_user()
    response = users_client.create(data)
    assert response.status_code == 201
    identity = response.json()["id"]
    try:
        assert response.json()["name"] == data["name"]
    finally:
        assert users_client.remove(identity).status_code == 204
EXPECTED RESULT
1 passed with the local API running. Builder, client, fixture and business assertion have separate responsibilities.

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

Should a page object own browser lifecycle by default?

Usually the fixture owns creating and closing the browser or driver, while page objects receive it as a dependency. Multiple page components can then work in the same intended session without silently creating extra sessions.

Which common mistake can affect this program or test?

An all-purpose base class quickly becomes tightly coupled. Prefer small, explicit dependencies and clear ownership.
