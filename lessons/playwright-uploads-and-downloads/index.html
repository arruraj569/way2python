Playwright uploads and downloads

Locators & interactions · Complete program, tricky exercise, and interview answers

The idea

Use set_input_files for a file input and expect_download for a download triggered by a click. Check the file content or expected business result. Temporary files make the exercise independent of machine-specific directories.

A complete program to try.

BEFORE YOU RUN

Save the entire program in test_playwright_uploads_and_downloads.py. Open a terminal in that file’s folder and activate your project’s virtual environment. Commands go in the terminal; the program goes in the .py file.

Install once in your activated environment: python -m pip install pytest-playwright.

Install Chromium once: python -m playwright install chromium. Browser test files use fixtures supplied by the pytest plugin.

The Way2Python site must be running at localhost:8080/way2python. Selenium also needs an installed browser such as Chrome.

Run: python -m pytest test_playwright_uploads_and_downloads.py -q --base-url http://localhost:8080/way2python

On macOS/Linux outside a virtual environment use python3; on Windows use py. The beginner guide explains both.

test_playwright_uploads_and_downloads.pyDownload program ↓
COMPLETE PYTHON PROGRAM
from playwright.sync_api import Page, expect

def test_practice(page: Page, base_url):
    page.goto(f"{base_url}/practice.html")
    page.get_by_label("Upload a text file").set_input_files({
        "name": "sample.txt", "mimeType": "text/plain", "buffer": b"automation notes"
    })
    expect(page.get_by_test_id("file-result")).to_have_text("Loaded: sample.txt · automation notes")
    with page.expect_download() as download_info:
        page.get_by_role("button", name="Download sample CSV", exact=True).click()
    assert download_info.value.suggested_filename == "test-results.csv"
EXPECTED RESULT
1 passed; the uploaded text and download filename are checked.

Read it step by step.

Read from the top. A function or class body does not run just because you defined it; look for the call, or let pytest call a test function.

  1. Line 1: Import playwright.sync_api. This makes the named library tools available; third-party packages must be installed first.
  2. Line 3: Define test_practice(page, base_url). Its body runs when called by pytest, which supplies fixture arguments.
  3. Line 4: Navigate the browser to the indicated application page. The target site must be running and reachable.
  4. Line 5: Call page.get_by_label('Upload a text file').set_input_files with the shown arguments. Read its result contract before assuming a successful call means the behavior was correct.
  5. Line 8: Check the browser’s observable state with a retrying Playwright expectation. It must become correct before the timeout.
  6. Line 9: Enter the with block and use its resource within the indented body. Its context manager performs exit handling even if the body raises an error.
  7. Line 11: Check download_info.value.suggested_filename == 'test-results.csv'. The program continues if this is true and raises AssertionError if it is false.

INTERVIEW PRACTICE · EXPLAIN THE WHY

Talk it through.

Answer in your own words first. Then check the explanation and connect it to the programs above.

What should you check beyond a download’s filename or extension?

Inspect the file contents, expected columns or schema, and relevant business values. A .csv filename can still contain an error page. Capture the download event before clicking and store it in a test-owned temporary path.

Which common mistake can affect this program or test?

A successful download event does not prove correct file contents. Inspect the downloaded artifact.
