Repository for Test Data in Python and Selenium

Python & Selenium approaches · Complete program, tricky exercise, and interview answers

First time writing Python?Start from zero →Read the punctuation guide ↗

The idea

A repository gives test code a small interface for getting data. Storage may be an in-memory collection, JSON or a service. The test asks for a case instead of knowing how storage works.

Python & Selenium approaches · Everyday

Use it in daily work.

Keep named valid and invalid login cases in one location, read the required case for a daily regression test, and copy mutable data before using it.

Know the tradeoff.

This example is a test-data repository inspired by Repository, not a full persistence layer. Never store real secrets in a sample data file; supply them through the environment.

COMPLETE PYTHON PROGRAM
from copy import deepcopy

class CaseRepository:
    def __init__(self, cases):
        self.cases = deepcopy(cases)
    def get(self, name):
        return deepcopy(self.cases[name])

repository = CaseRepository({"valid": {"email": "learner@example.test"}})
first = repository.get("valid")
first["email"] = "edited@example.test"
print(first["email"])
print(repository.get("valid")["email"])
EXPECTED RESULT
edited@example.test
learner@example.test

COMPLETE SELENIUM PROGRAM
"""Run against the local Way2Python lab with Selenium and installed Chrome."""
import os
from contextlib import contextmanager
from copy import deepcopy
from dataclasses import dataclass
from urllib.parse import urlsplit
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait, Select
from selenium.webdriver.support import expected_conditions as EC
from selenium.common.exceptions import TimeoutException

BASE_URL = os.getenv("WAY2PYTHON_URL", "http://localhost:8080/way2python").rstrip("/")

def create_driver():
    options = webdriver.ChromeOptions()
    options.add_argument("--headless=new")
    return webdriver.Chrome(options=options)

@contextmanager
def browser_session(factory=create_driver):
    driver = factory()
    try:
        driver.get(BASE_URL + "/practice.html")
        yield driver
    finally:
        driver.quit()

def control(driver, selector):
    return WebDriverWait(driver, 5).until(
        EC.element_to_be_clickable((By.CSS_SELECTOR, selector)))

def fill(driver, selector, value):
    field = control(driver, selector)
    field.clear()
    field.send_keys(value)

def wait_text(driver, selector, expected):
    WebDriverWait(driver, 5).until(
        lambda current: current.find_element(By.CSS_SELECTOR, selector).text == expected)
    return driver.find_element(By.CSS_SELECTOR, selector).text

def login(driver, email="learner@example.test", password="python123"):
    fill(driver, "#email", email)
    fill(driver, "#password", password)
    control(driver, "#login-form button[type=submit]").click()

def save_profile(driver, name, track="selenium"):
    fill(driver, "#display-name", name)
    Select(control(driver, "#track-select")).select_by_value(track)
    control(driver, "#save-profile").click()


class LoginCases:
    def __init__(self):
        self.cases = {
            "valid": {"email": "learner@example.test", "password": "python123", "expected": "Welcome, learner!"},
            "invalid": {"email": "learner@example.test", "password": "wrong", "expected": "Invalid credentials"},
        }
    def get(self, name):
        return deepcopy(self.cases[name])

def main():
    with browser_session() as driver:
        cases = LoginCases()
        for name in ("valid", "invalid"):
            case = cases.get(name)
            login(driver, case["email"], case["password"])
            assert wait_text(driver, "#login-status", case["expected"]) == case["expected"]
    print('Independent repository login cases passed')

if __name__ == "__main__":
    main()
EXPECTED RESULT WHEN RUN LOCALLY
Independent repository login cases passed
Read the Selenium program step by step
  1. Imports provide browser creation, locators, waits and select controls.
  2. browser_session creates a fresh browser, opens the local lab, and quits in finally. Factory and template examples own this context inside their workflow.
  3. fill clears a field before typing. wait_text polls for the exact observed result instead of pausing for an arbitrary delay.
  4. The pattern’s classes or functions sit between these helpers and main. Follow main to see the actual journey and assertions.
  5. The final message prints only after assertions succeed and the owned browser closes.

from copy import deepcopy

cases = {"valid": {"roles": ["reader"]}}
shallow = cases.copy()
shallow["valid"]["roles"].append("editor")
independent = deepcopy(cases)
independent["valid"]["roles"].append("admin")
print(cases["valid"]["roles"])

A shallow copy shares nested objects. A deep copy isolates nested roles so a test cannot silently change another test’s input.

How do you isolate test data returned by a repository?

Return immutable values or independent copies, use unique records for server tests, and clean up only records the test owns. An in-memory copy cannot isolate server-side state.

Which common mistake can affect this program or test?

This example is a test-data repository inspired by Repository, not a full persistence layer. Never store real secrets in a sample data file; supply them through the environment.
