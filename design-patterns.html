NEW TO THIS?

Start with a small problem.

A class groups related data and operations. An object is one instance of a class. An interface describes what operations a collaborator offers. A pattern organizes these responsibilities so a repeated change is easier to handle.

First learn functions, classes, exceptions and basic Selenium. Then start with page objects, components, injection and cleanup. “Everyday”, “Situational” and “Advanced” are learning priorities for this library, not official pattern categories.

START WITH THE CHANGE

Which pattern fits?

A practical starting point. Use a function when an extra abstraction adds no value.

Your daily problemConsiderWhat owns the change?
Locators change in many testsPage Object Model →The page owns locators and operations; the test owns assertions.
Forms and tables repeat across pagesPage Component Objects →Small components own a real page region.
A page creates its own browserDependency Injection →Setup supplies the driver; the page receives it.
A failed test leaves Chrome openContext Managers →The resource owner always quits its session.
A creator workflow needs different browsersFactory Method →An overridable method chooses the product.
A case needs many readable data choicesBuilder →Construction produces independent finished data.
Two assertion rules need the same callerStrategy →A supplied callable chooses the comparison rule.
Several pages repeat one business journeyFacade →One coordinator exposes a small journey operation.
Actions need extra reportingDecorator →A wrapper preserves the action contract and errors.
Results need several listenersObserver →The publisher broadcasts; subscribers report.

Interview distinctions to practise.

Factory Method / Abstract Factory
An overridable creation hook for a workflow / a compatible family of products.
Adapter / Facade / Proxy / Decorator
Translate an interface / simplify a journey / control access / add behavior while preserving the interface.
Strategy / State / Template Method
Supply an algorithm / model lifecycle transitions / customize fixed workflow hooks through inheritance.
Builder / Fluent Interface
Construct a finished product in steps / design readable chained operations. A builder can be fluent.
Composition / Composite
An object has collaborators / a recursive tree gives leaves and containers a shared operation.

Singleton, Flyweight, Interpreter and Visitor have narrower uses in browser testing. Learn their tradeoffs; introduce them only when the repeated problem warrants the extra structure.
